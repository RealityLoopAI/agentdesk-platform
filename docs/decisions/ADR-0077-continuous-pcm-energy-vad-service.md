# ADR-0077: 持续 PCM 能量 VAD 小环监听服务

**状态**：Accepted
**日期**：2026-07-30

## 背景

ADR-0076 的固定时长 realtime CLI 已验证小环 RTP/Opus 接收，但人工协调启动时序会漏掉整句。真实数据表明底噪约 `-47 dBFS` RMS，完整人声约 `-28 dBFS` RMS，具备使用简单能量门限自动切句的条件。

## 决策

1. 保持一个 FFmpeg 子进程持续将 SDP/RTP/Opus 解码为 stdout 上的 16 kHz、单声道、16-bit PCM，不再为每句话重启接收器。
2. Node 按 20 ms 帧计算 RMS dBFS，默认使用 `-43 dBFS` 门限、100 ms 连续起句、300 ms 预录、800 ms 尾静音、400 ms 最短语音和 20 秒最长语句。
3. VAD 与方舟处理解耦：PCM 循环只生成有界 utterance，独立 worker 串行处理；队列满时服务失败，不静默丢句。
4. 默认 capture-only。持续 process 模式必须同时显式提供处理开关和外部上传确认，该确认覆盖本次服务生命周期内检测到的语句。
5. 单句处理失败不终止监听；FFmpeg 退出、无首包、队列溢出是服务级错误。信号退出会停止 FFmpeg、按最短时长规则完成当前句并排空队列。
6. 完成的 utterance 在写 WAV 前做有界峰值归一化，默认目标 `-3 dBFS`、最大增益 30 dB，以补偿小环已观测到的低麦克风电平。

## 后果

- **Positive**：监听在用户说话前已经 ready，消除人工启动竞态。
- **Positive**：不新增原生或神经网络 VAD 依赖，算法可确定性测试和按现场电平调参。
- **Positive**：模型延迟不会阻塞 PCM 接收，且队列资源有明确上限。
- **Negative**：能量 VAD 不区分人声与高能噪声，环境变化可能需要调整门限。
- **Negative**：第一版不是系统级 daemon；进程拉起和崩溃重启仍需运营层管理。

## 被否决方案

- 继续固定 20 秒分段：延迟高、空白多，并保留启动竞态。
- 首版引入神经网络 VAD：增加模型、原生运行时或资源依赖，当前样本不足以证明必要。
- 模型处理时暂停接收：会漏掉下一句话。
