## Context

当前 Web 消息输入组件由 `MessageComposer` 独立维护草稿并只向上抛出文本，`ConversationPage` 再调用现有 `submitMessage`。输入框底栏左侧仅展示键盘提示，右侧为发送按钮。项目已有 React、Lucide 图标和 Tailwind 样式，但没有通用 Select/Popover 组件。

本次只验证模型选择入口的视觉与交互，不建立真实模型能力契约。尤其不能让静态选择值进入消息请求，否则前端占位数据会被误认为经过服务端授权和支持的运行配置。

## Goals / Non-Goals

**Goals:**

- 在不挤压消息输入和发送操作的前提下，提供接近参考图的模型按钮及弹出列表。
- 支持鼠标、触摸、键盘和读屏使用，并适配窄屏。
- 切换后立即更新按钮文案和列表选中态。
- 保持实现局部、无后端副作用、无新增依赖。

**Non-Goals:**

- 不改变真实 Provider、模型、推理强度或容器配置。
- 不修改 `submitMessage`、Web API、数据库或服务端权限校验。
- 不从后端拉取模型清单，不校验模型可用性，不记录用户偏好。
- 不承诺演示模型名称对应当前部署能力。

## Decisions

### 1. 选择器放在输入框底栏左侧

模型按钮替代底栏左侧的主要位置，键盘提示在空间允许时保留为次要文案；发送按钮继续固定在最右侧。弹层向上展开，避免超出页面底部。

备选方案是放入会话 Header。该位置容易让用户理解成“整个会话已切换模型”，与本次仅做前端状态的边界冲突，因此不采用。

### 2. 模型清单使用组件旁的静态展示数据

初始选项为：

- `auto` — 自动选择（默认，按钮显示“自动选择”）
- `gpt-5.6-sol` — GPT-5.6 Sol
- `gpt-5.6-terra` — GPT-5.6 Terra
- `claude-opus-5` — Claude Opus 5
- `claude-sonnet-5` — Claude Sonnet 5
- `gemini-3.6-flash` — Gemini 3.6 Flash

每项只包含前端 `id`、显示名和可选说明。选择值由 `MessageComposer` 内部 state 保存，刷新页面后回到默认值，不写 `localStorage` / `sessionStorage`，也不加入 `onSend` 参数。

备选方案是从 Provider 配置或 API 读取。那会引入模型枚举、权限、可用性和消息路由契约，超过本次范围。

### 3. 使用受控按钮与可访问单选弹层

触发器使用 `button`，带 `aria-haspopup="listbox"`、展开状态和当前选择名称。弹层使用 `listbox` / `option` 单选语义，展示当前项勾选；支持 Enter/Space 打开与选择、上下方向键移动、Escape 或点外部关闭，并提供可见焦点样式。

实现可以拆成 `ModelSelector` 小组件，由 `MessageComposer` 组合使用。该方案比原生 `<select>` 更接近参考图，也能保留完整键盘语义；不引入新的 Popover 依赖。

### 4. 禁用态与消息提交完全解耦

当 Composer 因归档或提交中禁用时，模型按钮同步禁用并关闭弹层。发送仍只提交经过 trim 的消息文本；选择模型不会触发请求、Toast 或伪造的成功状态。

## Risks / Trade-offs

- [静态模型名称可能被误解为真实能力] → 不在列表中添加免责声明或预览提示；改由组件边界和自动化测试确保选择值不进入 `onSend`，真实模型接入另立变更。
- [手写弹层的可访问性容易遗漏] → 用明确的 listbox 单选语义、键盘用例和焦点恢复测试覆盖，不实现多层菜单或搜索。
- [窄屏底栏空间不足] → 小屏隐藏键盘提示，按钮使用截断和最大宽度，发送按钮保持可见且不收缩。
- [后续接入真实模型时静态数据被直接沿用] → 将展示选项集中定义并保留“UI-only”注释；真实接入必须另起变更，设计服务端权威清单与授权契约。

## Migration Plan

这是新增且可逆的前端 UI。上线只需随 Web 静态资源发布；回滚时删除选择器并恢复原底栏提示即可，不涉及数据迁移。

## Open Questions

- 真实模型选择能力未来应按“每条消息”还是“每个会话”生效，留待独立后端契约提案决定。
