## Context

固定分段 realtime CLI 已证明小环 RTP/Opus、macOS FFmpeg 和方舟链路可用，但真实操作暴露了启动竞态：用户在 `xiaohuan_realtime_started` 前说话会完全漏录或只保留句尾。常驻服务应先稳定打开 RTP 流，再由音频本身触发切句。

已验证电平给出可用校准依据：纯底噪约 `-47 dBFS` RMS，完整人声测试约 `-28 dBFS` RMS、峰值 `-6 dBFS`。服务应允许覆盖默认门限，因为实验室噪声和麦克风增益可能变化。

## Goals / Non-Goals

**Goals:**

- 单个 FFmpeg 子进程长期接收 RTP/Opus 并向 Node 输出原始 PCM。
- 自动检测一句话开始和尾静音，保留预录，避免吞掉首音节。
- 监听与方舟处理解耦；模型慢时仍继续消费 PCM，但队列必须有界。
- capture-only 默认；process 模式需显式确认持续外部上传。
- 单句失败不终止监听，资源溢出或 FFmpeg 退出则明确失败。

**Non-Goals:**

- 本轮不引入神经网络 VAD、说话人识别、唤醒词或逐字流式 ASR。
- 不安装系统级 launchd job；提供长期运行命令和后续部署说明。
- 不接数据库、Backend Gateway、Feishu 或 Bitable。

## Decisions

### 1. FFmpeg 输出原始 PCM，Node 按 20 ms 帧做 VAD

FFmpeg 使用 SDP/RTP/Opus 输入，stdout 输出 `s16le`、16 kHz、单声道。Node 用字节累积器切成 640 字节的 20 ms 帧，计算每帧 RMS dBFS。

这避免不断启停 FFmpeg和固定 segment muxer，也无需新增原生 VAD 依赖。能量 VAD 对噪声敏感，但当前电平区分足够，且所有参数可配置和测试。

### 2. 两态 VAD 加预录和迟滞

默认门限 `-43 dBFS`。连续 5 个高于门限的帧才从 idle 进入 speech；idle 保留最近 300 ms 预录。speech 中连续 800 ms 低于门限即完成一句，最短有效语音 400 ms，最长 20 秒强制切句。

连续帧和尾静音形成迟滞，避免单个脉冲噪声触发；预录解决起句判断带来的首音节丢失。低于最短语音的片段记安全事件后丢弃。

### 3. 监听循环与串行工作队列分离

PCM/VAD 循环只生成有界 `Buffer` 并入队，不等待方舟。独立 worker 串行写临时 WAV、校验并处理。队列默认最多 4 句；达到上限时服务失败关闭，不静默丢弃语音。

单句方舟失败记录安全错误后继续处理后续句子。捕获模式输出本地 WAV 元数据；处理模式输出一行一个 `experiment-audio.v1`。

每个完成 utterance 在写 WAV 前做有界峰值归一化：默认目标 `-3 dBFS`，最大增益
30 dB。它补偿小环低增益，但不会无限放大纯底噪；目标和最大增益均可配置。

### 4. 长期运行仍保持显式隐私边界

默认 capture-only。process 模式仍要求 `--process --allow-external-upload`，其含义升级为授权本次服务生命周期内检测到的每个语句上传方舟。默认临时目录在退出后清理，显式输出目录或保留选项才保存 WAV。

### 5. 信号结束时完成当前句并排空有界队列

SIGINT/SIGTERM 先停止 FFmpeg；若当前 speech 已达到最短长度则作为最终句入队，然后等待已入队工作完成，最后清理。FFmpeg异常退出、无 PCM 首包超时和队列溢出是服务级错误。

## Risks / Trade-offs

- **持续噪声高于门限** → 门限和连续帧可调；最长句强制切分防止无限缓存。
- **轻声低于门限** → 预录不能恢复从未越过门限的语音；文档提供实时 dBFS 校准模式。
- **方舟慢导致积压** → 有界队列；短时间积压允许，满时停止而非丢句。
- **单句上传失败** → 记录错误并继续监听；不自动重试，避免重复披露和费用。
- **服务意外退出** → FFmpeg 退出和信号均有安全日志；系统级自动拉起留给后续 launchd 部署。

## Migration Plan

1. 保留固定分段 realtime CLI 作为诊断和回退入口。
2. 新增 VAD 核心纯函数和流式服务 CLI。
3. 用合成 PCM 覆盖边界，再用已保留的真实小环 WAV 回放校准。
4. 以 capture-only 启动真实常驻服务，确认自动切句后再显式启用持续上传。

## Open Questions

- 不同实验室环境是否需要启动时自动估计噪声底；第一版先使用显式可调门限。
- launchd 自动启动、日志轮转和崩溃拉起是否作为下一轮部署工作。
